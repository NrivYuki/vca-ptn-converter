# 規格との対応

このツールが読み込む VCA と書き出す VCA が、DCS v3.14 のどの決まりに関わり、どう扱っているかの一覧です。読み込み(`fromVCA`)は受ける側、書き出し(`toVCA`)は送る側です。PTN・JOB は、中身が VCA のテキストなので、VCA と同じ扱いです。

- 「番号」は [vca-guide](https://github.com/NrivYuki/vca-guide) の [docs/requirements.md](https://github.com/NrivYuki/vca-guide/blob/main/docs/requirements.md) の番号です(R 義務・S 推奨・O ほかの言い方の義務)。番号の無い決まり(データ型の定義など)は節の番号で書きます。
- 「扱い」は、テスト(`tests/conformance.test.js` で確かめる)・対象外(このツールに当てはまらない)・利用者(書き出したファイルを使う人が守る)のどれかです。テスト以外は理由を書きます。
- 「送る側」は書き出しで守ること、「受ける側」は読み込みで相手が決まりを破ったときの扱いです。- はその側が無いことを示します。
- VCA の読み書きそのもの(レコードの区切り、エスケープ、玉型の形式など)は、`vca-parser.js`(vca-guide の `src/vca-parser.js` と同じもの)が受け持ち、vca-guide のテストで確かめています。この表は、このツールの処理に関わる決まりだけです。
- どのテストが確かめているかは [conformance-tests.md](conformance-tests.md) にあります(`tools/trace.js` が作る)。`tools/trace.js --check` は、次のどれかがあれば失敗します。
  - テストの無い「テスト」の行(送る側・受ける側のそれぞれ)
  - 正常系(正常・規格の例)と異常系(異常・境界)のどちらかが欠けた行([異常系を求めない行](#異常系を求めない行)を除く)
  - 表に無い番号を指すテスト、理由の無い行

## 異常系を求めない行

書き出す形が入力によらず決まっている行です。規格に反するデータを作る入力が無いので、異常系(誤った入力を誤りにする・境界の値)のテストを作れません。正常系は、両眼・片眼、点数、元の形式を変えて確かめます。

| 番号 | 異常系を求めない理由 |
|---|---|
| R036 | 半径を測る向きは計算で決まり、入力で変わらない |
| R221 | 角度の読み取りは vca-guide のパーサーが受け持ち、角度の誤りは vca-guide のテストで確かめる |
| R011 | エスケープの読み取りは vca-guide のパーサーが受け持ち、誤りは vca-guide のテストで確かめる |
| R044 | 同上 |

## 規格に書かれていないところ・食い違うところ・守っていないところ

| 場面 | 決めたこと | 理由 |
|---|---|---|
| JOB が無い | `JOB=?` を書く | 7.5.4 は、ファイルの中身をデータパケットの決まりで書き、ジョブのデータなら 2 行目を JOB にするとしている。表 A.2 の JOB は、ジョブを示せないアップロードの装置に不明値 `?` を送らせている(R225)。ファイルはアップロードではないが、7.5.4 がデータパケットの決まりに従うとしているので、同じ決まりを当てはめた。保存するファイルの名前には、元のファイル名を使う |
| 文字 127(DEL) | JOB に使える | 5.1.8.1 は 32-127 の文字を認め、3.2.12 は制御文字を「32 未満の文字」と定めている。127 はどちらからも除かれない |
| 値に ; を含むレコード | 引き継がず、知らせる | 5.1.8.1 は、どのデータ型でも ; を値に使えないとしている。読み込みでは、引用符の中の ; を値として受け取る(DCS Host Simulator がそう送るため。vca-guide の U5)が、そのまま書くと区切りと見分けられず値の数が変わる。引用符を付けて書いても 5.1.8.1 に反する |
| 誤りのある DRILLE | 穴を描かず、引き継がない | 基準が ? の穴などは位置を決められない。誤った位置に穴をあけるデータを渡さないため |
| 元の玉形の原点がずれている | 箱の中心に合わせ直して書く | 5.4.8 は半径データを箱の中心に置くとしている。合わせ直すと形の位置は箱の中心に移るが、形そのものは変わらない |
| 片眼の玉形で CIRC の左右が違う | 反対の眼は左右反転で作り、大きさは変えない(守っていない) | 5.4.9.4 は、CIRC の差を反対の眼の大きさの変更(CSIZ)とみなすとしている。周長に合わせて形を縮め・広げる処理はこのツールに無いので、知らせるだけにした |
| ファイルの中の DRILLE | 元の DRILLE を引き継ぐか、図面の穴を基準 C(箱中心)で書く | 規格の本文が食い違っている。5.5.1.5 の始めは、穴あけの基準を「初期化で、または要求ごとに」取り決めるとし、5.5.3 も、初期化をしないときは要求のパケットに DRLFMT を入れるとしている。一方、5.5.1.5 の終わりは、初期化が無ければ DRILLE は使えないとしている。ファイル(7.5)には初期化も要求も無く、7.5 にも DRILLE の扱いは書かれていない。7.5.5 が縁なしフレームの穴あけのファイル(REQ=FRM)を挙げていることから、ファイルで穴を渡すことは想定されているとみなした。読む機器が DRILLE と基準 C に対応しているかは利用者が確かめる |
| 箱の中心の許容差 | 0.01 mm | 規格(5.4.8)は許容差を定めていない。R の値の 1 単位が 0.01 mm(5.4.15.4)なので、書いた半径で表せる細かさを許容差にした |
| R の行の長さ | 15 個ずつ。80 文字を超える行だけ分ける | 規格(5.4.15.1)が決めているのは 80 文字の上限だけで、1 行の個数は決めていない。これまでの出力と同じ 15 個ずつにし、上限を超える場合だけ分ける |
| 「PTN・JOB は元のファイルのまま」 | 読み込んだファイルの中身をそのまま保存する | 利用者が選んだときだけの動きで、中身を変えないことが目的なので、規格に合わない中身も直さない |
