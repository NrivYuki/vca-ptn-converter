# vca-ptn Converter

眼鏡の玉形(レンズの外形)を、VCA(OMA / DCS)・JOB・PTN・SVG・DXF の間で変換するツールです。ブラウザで開くだけで動き、ファイルはどこにも送信しません。

**公開ページ: ** https://nrivyuki.github.io/vca-ptn-converter/index.html

> **前提**
>
> JOB・PTN ファイルの扱いは、[OptiBoard](https://www.optiboard.com/)(眼鏡業界の英語フォーラム)の OMA 関連スレッドと、公開されている各メーカーの取扱説明書から得た情報だけに基づいています。実機が書き出したファイルの中身は確認していません。メーカーごとの JOB・PTN の定義と出典は [docs/job-ptn.md](docs/job-ptn.md) にまとめています。

## 使い方

1. [公開ページ](https://nrivyuki.github.io/vca-ptn-converter/index.html)を開く(手元で使うときは `index.html` をブラウザで開く。サーバーは不要。書体は Google Fonts から読み込み、つながらないときは端末の書体で表示する)
2. 「読み込み」のタブでファイルを選ぶか、画面のどこかに置く(テキストの貼り付けや「サンプル」でも読み込める)
3. SVG・DXF のときは、「図面」の表示と「読み込み」のタブの「輪郭の割り当て」で、どの輪郭が右眼・左眼・穴かを確かめる(下の「SVG・DXF の輪郭の割り当て」)
4. 右の面で玉形の図と角度ごとの半径のグラフを、「結果」のタブで寸法(HBOX・VBOX・周長・FED)を確かめる。必要なら「設定」のタブで変える。図の上にマウスを置くと、その角度の半径が分かる
5. 画面下のボタン(SVG・DXF・VCA・PTN・JOB)で保存する。ファイル名と書き出す中身は「書き出し」のタブで確かめられる

## できること

| 読み込み | 書き出し |
|---|---|
| VCA(.oma / .vca / .dcs)。形式 1・2・3・4、角度モード E・U・C | SVG(単位 mm) |
| 中身が VCA のテキストになっている .job / .ptn | DXF(R12、単位 mm、眼ごとにレイヤー R / L、穴はレイヤー HOLE) |
| SVG(曲線・transform・単位に対応) | VCA(REQ=FIL、形式 1、等角度、点数は 360-1440 から選べる) |
| DXF(LWPOLYLINE・POLYLINE・LINE・ARC・CIRCLE・ELLIPSE・SPLINE) | PTN / JOB(VCA のテキストを、Nidek 機の USB メモリ用の 16 桁の名前にしたもの) |

- 両眼の輪郭が並んだ SVG / DXF は、正面から見て左側を右眼として読み込み、間隔を DBL とします
- 片眼しかないときは、反対の眼を左右反転して作れます(箱中心基準の穴も反転します)

## SVG・DXF の輪郭の割り当て

SVG・DXF は図面のデータなので、どの線が玉形でどの線が穴かは書かれていません。そこで、閉じた輪郭に大きい順の番号を付けて一覧にし、それぞれに「右眼・左眼・穴・使わない」を割り当てます。

- 既定の割り当て: 図形の名前(SVG の id・Inkscape のレイヤー名、DXF のレイヤー名)に `R`・`eye-R`・`right`・`右` などがあればそれに従い、`hole`・`drill`・`穴` を含むものは穴にする。名前が無ければ、いちばん大きい輪郭(両眼なら同じくらいの大きさで離れた 2 つ)を玉形にする。ほかの大きな輪郭を囲む輪郭(図面の枠など)は玉形にしない。玉形の内側にある小さい輪郭(長辺 8 mm 以下)は穴にする
- 「読み込み」のタブの表で変えられるほか、「図面」の表示で輪郭をクリックするたびに 右眼→左眼→穴→使わない と切り替わる
- 穴は、中心を含む玉形の眼の箱中心からの位置にして、VCA・PTN・JOB には `DRILLE`(基準 C)で書く。輪郭は主軸の向きに測り、丸穴(直径)か長穴(両端の円の中心と幅)に当てはめる。矩形の切り欠き、角度、深さは扱わない
- 線の意味を選べる。VCA の `TRCFMT` の最後の欄(対象)に書く

| 線の意味 | 扱い | 対象 |
|---|---|---|
| フレームの溝の底 | そのまま使う | F |
| フレームの内側の線 | 指定した溝の深さ(既定 0.5 mm)だけ外へ広げる。溝の深さはフレームによって違うので、実物に合わせる | F |
| 型板の外形 | そのまま使う | P |
| デモレンズの外形 | そのまま使う | D |

このツールが書き出す SVG(`eye-R`・`holes-R` などの id)と DXF(レイヤー R・L・HOLE)は、読み込み直すと同じ割り当てになります。

SVG の直線だけの図形(`M`・`L`・`H`・`V`・`Z` だけの `path`、`polygon`、`polyline`、`line`、角の丸くない `rect`)は、頂点をそのまま読みます。曲線を含む図形は、長さに沿って 0.05 mm ごとに点を取るので、とがった角はわずかに削れます。

## ファイル名の決まり

| 対象 | 決まり | 根拠 |
|---|---|---|
| PTN / JOB | 「銘柄名-番号」(ハイフンを含めて 16 桁)か、番号だけ(16 桁)。足りない桁は番号の先頭を 0 で埋める(例: `S1-0000000152152.ptn`、`0000000000123456.ptn`) | ICE 900 の取扱説明書、OptiBoard、販売店の手順書 |
| PTN / JOB | 銘柄名は半角英数字で、英字を 1 文字以上含む 12 文字まで(ハイフンは使えない)。英字は大文字にする | ME-1000・Me 1200・LEXCE の取扱説明書 |
| PTN / JOB | 拡張子は小文字(`.ptn`)か大文字(`.PTN`)を選べる。USB メモリ(FAT32)は区別しない | 資料によって書き方が違うため |
| SVG / DXF / VCA | JOB 番号(無ければ読み込んだファイルの名前)をファイル名にする。Windows で使えない文字(`\ / : * ? " < > \|`、空白)は `_` に、制御文字は削除、最後の `.` と空白は削る。予約された名前(`CON`、`NUL`、`COM1` など)は先頭に `_` を付ける | Windows のファイル名の決まり |

## できないこと・注意

- **機器が独自の形式で書き出した .job / .ptn は読み込めません。** 形式が公開されていないためです。機器を VCA 出力に設定するか、メーカーの変換ソフトで VCA にしてから使ってください
- 書き出した .ptn / .job を機器が読めるかどうかは、機種や設定によります(OptiBoard では、読めたという報告と読めなかったという報告の両方があります)
- 内側にえぐれた形(中心から見て輪郭と 2 回以上交わる形)は、等角度の VCA では正確に表せません。いちばん外側の輪郭で近似し、警告を出します
- 点数の下限は規格(DCS v3.14)に定められていません。ただし、機器が対応している点数は機種ごとに違います(400 点以上が一般的)。機器が受け付けない点数を送ると、ステータス 17(非対応のトレース形式)が返ることがあります
- Z(サグ)データは、どの形式にも書き出しません。VCA・PTN・JOB には、眼ごとに `ZFMT=0`(サグなし)を書きます
- VCA の JOB は、半角の英数字と記号の 12 文字までです(規格の limited 型)。区切りなどに使う文字(`; = , * ? |`)と制御文字は使えません。超えたり使えない文字があったりすると誤りを知らせ、VCA・PTN・JOB は書き出しません(ファイルの JOB が長いときは、JOB 番号の欄で直してください)。JOB が無ければ不明値の `JOB=?` を書きます
- VCA の半径は、箱の中心から測って書きます(規格 5.4.8)。読み込んだ VCA の原点が箱の中心からずれていれば知らせ、箱の中心に合わせ直して書き出します
- R の行は 15 個ずつです。値が 5 けたになって 1 行が 80 文字を超えるときだけ、80 文字に収まるように分けます
- 片眼だけの VCA で CIRC の左右が違うとき、規格はその差を反対の眼の大きさの変更とみなしますが、このツールは反対の眼を左右反転で作るだけで、大きさは変えません(知らせます)
- VCA の穴あけデータは、箱中心基準(C)のものだけを表示と SVG / DXF に描きます。縁・外接箱・グループ基準の穴は描きません。VCA・PTN・JOB では、元の VCA に書かれていたレコードをそのまま引き継ぎます。ただし、基準が `?` などの誤りのある `DRILLE` は、誤った位置に穴をあけないよう描かず、引き継ぎません。値に `;` を含むレコード(引用符で囲んだものなど)も、規格では書けないので引き継ぎません(どちらも知らせます)
- `DRILLE` の基準は、規格では初期化(または要求パケット)の `DRLFMT` で取り決めます。ファイルにはその取り決めが入らないので、機器が箱中心基準(C)に対応しているか確かめてください
- 単位の書かれていない SVG / DXF は、1 単位 = 1 mm とみなします。違う場合は設定の「1 単位 = ? mm」で直してください

## ファイル

```
index.html       画面
converter.js     変換処理(VCA・SVG・DXF の読み書き、等角度への測り直し、16 桁の名前)
vca-parser.js    VCA の読み書きライブラリ(vca-guide からそのまま使用)
vca-records.js   DCS v3.14 附属書 A のラベル定義表(vca-guide からそのまま使用)
sample-data.js   「サンプルを読み込む」用のデータ
samples/*.vca    サンプルファイル(下記)
docs/job-ptn.md  メーカーごとの JOB・PTN の定義と出典
docs/conformance.md  規格(DCS v3.14)との対応(どの決まりをどう扱うか)
tests/           テスト(conformance.test.js: 読み書きが規格の決まりを守るか。formats.test.js: 読み書きの形式の組み合わせ。spec.js: テストの書き方。ui/: 画面の検査)
tools/trace.js   規格との対応の表とテストを突き合わせる
tools/mutate.js  実装をわざと壊し、テストが見つけるかを確かめる(ミューテーションテスト)
```

## テスト

```sh
npm test
```

読み込みと書き出しが規格の決まりを守るか(ファイルの 1・2 行目、JOB の文字、左右のレコード、TRCFMT と R の書式・向き・原点、引き継ぐレコード、DRILLE の誤りの扱い、形式 2 の規格の例など)を `tests/conformance.test.js` で確かめます。

読み込める形式と書き出せる形式の組み合わせは、`tests/formats.test.js` ですべて通します。元のデータ(VCA の両眼・片眼・不等角度・形式 2・穴あり、それを DXF にしたもの、隣に vca-shape-maker があればその書き出し)ごとに、反対の眼を作る・作らない × 1 回目の書き出し(VCA・PTN・JOB・DXF)× 2 回目の書き出しで、読み直した眼・形・寸法・穴・JOB・DBL が変わらないこと、同じ形式で 2 回書くと中身が同じことを確かめます。SVG を通る組み合わせは、ブラウザが要るので画面の検査で確かめます。どの決まりをどのテストが確かめているかは [docs/conformance.md](docs/conformance.md) と [docs/conformance-tests.md](docs/conformance-tests.md) にあります。次のコマンドで突き合わせ、テストの無い決まりがあれば失敗します(GitHub Actions でも動かします)。

```sh
node tools/trace.js --check
```

テストが確かめているはずの処理を本当に確かめているかは、実装をわざと壊して試します(壊し方の一覧は `tools/mutate.js` にあり、1 つでもテストが通ってしまえば失敗します)。

```sh
npm run mutate
```

VCA の読み書きそのもの(`vca-parser.js`)は、vca-guide のテストで確かめています。

画面(書き出す VCA の JOB、誤りの知らせ、保存のボタン、引き継がないレコードの知らせ、SVG を通る組み合わせ、vca-lens-simulator の三面図の SVG の読み込み、VCA・PTN・JOB・DXF・SVG のファイルを読み込み欄と画面のほかの場所に置いたときの読み込み)は、Chrome をヘッドレスで動かして確かめます(Node.js 22 以上)。リポジトリのフォルダで実行し、画像は OS の一時フォルダの vca-ui-check に置きます。

```sh
npm run ui
```
